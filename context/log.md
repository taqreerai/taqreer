## 2026-05-15

- **fix** · `taqreer_hasUniformScript` — ALL split signals now gate on flex/grid parent → previous version still split mixed-script siblings (Arabic span + Latin span) even when the parent was block-level prose. Real example that regressed: `<div>أن تصبح <span>تقرير</span> منصة ... <span dir="ltr">workflow</span>.</div>` — Arabic emphasis span beside an LTR language island; the script-mismatch rule split them into 3 separate shapes, stranding the surrounding prose. New rule: block-level parents (`<p>`, plain `<div>`) ALWAYS return true (uniform); flex/grid parents keep the original script-mismatch + 2+ explicit-dir logic. Inline language emphasis in prose stays merged into one text frame regardless of script mix. Flex rows of distinct labels still split correctly. · `patches/dom-to-pptx+1.1.8.patch`
- **fix** · earlier (same session): `taqreer_hasUniformScript` dir-split now gates on parent's display → previous version triggered `false` on any 2+ explicit-dir children, which incorrectly fired for INLINE PROSE with multiple language islands (e.g. `<p>منصة ... <span dir="ltr">5 minutes</span> ... <span dir="ltr">3 hours</span> ...</p>`). New rule: dir-based split only when 2+ children with dir AND parent's computed display is flex / grid. Inline prose with multiple `<span dir="ltr">` emphasis spans now stays merged (single text frame). Function signature changed from `(children)` to `(node)` so it can read `getComputedStyle(node).display`. · `patches/dom-to-pptx+1.1.8.patch`
- **fix** · PASS 3 now CLAMPS growth to enclosing-container bounds (was: skip on nested) → the "skip if nested" version was over-conservative: small nested badges / numerals / labels ("01", "Fast Creation", "corporate teams") need PASS 3 slack to fit on one line inside their card cells; only the long-text-fills-card case needs to skip. New behaviour: find the smallest enclosing container (rect / roundRect with visible fill or border, card-like size). The growth budget on each side equals the gap between the text shape's edge and the container's interior edge — i.e. effectively the CSS padding on that side. Top-level text (no enclosing container) keeps the original slide-bounds clamp. Result: tight nested text grows up to the card's visible edge (one-line preserved), wide nested text can't overflow because available room is ~0. Container shapes are never modified. · `lib/export/bidi-postprocess.ts`
- **revert** · PASS 5 (card containment correction) → the previous approach grew CONTAINERS to fit inner shapes; broke real cards. Reverted, replaced with the containment guard above (PASS 3 skips nested text instead of growing containers — safer direction). · `lib/export/bidi-postprocess.ts`
